# ADR-0006: fsession lifecycle sensor, kernel floor 7.0+

## Status

Accepted (T06 round-8 rework, 2026-09-25). Implements the unanimous
4-model decision record (workspace `evidence/kcrypto-t06/W8-decision/DECISION.md`,
ratified with conditions A–D) and its guest-proven addendum.

## Context

The T06 request-lifecycle sensor first attached as four programs
(`fentry/`+`fexit/` per api site) with kernel pairing state (slot
table, ghost quarantine, overflow flag). Round-8 dual review returned
a NO-GO union over that split: entry/exit pairing across separately
attached programs cannot certify submit↔result identity, and the
slot machinery added failure modes (eviction, quarantine release,
async races) the evidence could not exclude.

Kernel 7.0 provides `BPF_TRACE_FSESSION` attach (value 58): one
program runs at function entry AND return under one link, with a
kernel-zeroed per-call session cookie and two session kfuncs
(`bpf_session_is_return`, `bpf_session_cookie`) to branch and carry
a caller-minted invocation id. Pairing state moves into the kernel
call itself — no slots, no quarantine, no cross-program join.

## Decision

1. The lifecycle sensor is two `fsession/` programs (one per api
   site), each running at entry and return under one link. Stale
   `fentry/`/`fexit/` lifecycle objects refuse at the section
   allowlist, fail-closed.
2. Kernel floor for the request-lifecycle sensor is 7.0+. The
   floor discriminator is FSESSION attach acceptance (type 58) at
   `BPF_PROG_LOAD` — guest-proven: the session kfuncs exist as
   vmlinux BTF FUNCs even on 6.12, so kfunc presence only gates a
   fail-closed pre-check, never the verdict. Pre-7.0 kernels
   refuse typed (`detect` reports `Unsupported`; direct bring-up
   fails the load with errno 22 plus a conditional pre-7.0 hint).
   No LTS backport commitment: 6.12 stays refused, not supported.
3. The rest of the product keeps its 6.12+ floor (aggregate
   spine, doctor, token flows). The split is per-sensor, and the
   runtime probe matrix (`doctor`, `fsession_capable` row) stays
   the authoritative gate — deploy on what `doctor` passes.
4. Loader rewrites sentinel kfunc stubs (`0x5F4B0001/0x5F4B0002`,
   plain `call imm`, zero `R_BPF_64_32`) to
   `BPF_PSEUDO_KFUNC_CALL` with vmlinux BTF FUNC ids before load
   (aya-ebpf 0.2.1 has no kfunc support; the rewrite is unit-tested
   and the stub codegen is pinned against the built object).
5. Sensor protocol is explicit ADMIT/DRAIN/CLOSED
   (arm-after-links, disarm-before-detach), identity is snapshotted
   pre-arm via raw `BPF_OBJ_GET_INFO_BY_FD` and re-verified after
   ingest (sticky validity; misses void exact counts in coverage),
   and the canary excludes foreign tracing links on its targets
   (H4 retirement exclusion).

## Consequences

- `docs/deployment.md` states the split floor; `doctor` gains the
  `fsession_capable` row (15-row matrix).
- VM qualification covers 7.0.y (mainline guest + headers +
  fixture build recipe) and 7.2.y canary rounds, plus a 6.12
  refusal proof. The 6.12 guest remains in the matrix as the
  refusal control, never a pass target.
- Api-returns stays `fexit/`-only (frozen C1); the fsession
  rework touches the lifecycle profile only.
