# ADR-0005: kcrypto lifecycle semantics + payload-v1

## Status

Accepted (T05, 2026-09-24).

## Context

T04 qualified the hook surface and produced raw edge observations
(submit/return/callback per request id). Consumers need one
certificate per request — how it completed, with what native
status, over what measured span — without inventing queue
semantics from errno alone, without guessing joins across
reordered edges, and without unbounded memory. The reduced
records must cross the report boundary in a versioned payload
that fails closed on unknown versions.

## Decision

- A pure bounded `LifecycleReducer`
  (`crates/kryprobe-core/src/kcrypto/`) folds `Edge`s
  (Submit/Return/Callback/Gap) into `RequestRecord`s. Terminal
  truth comes only from adapter dispositions; the reducer never
  infers queue semantics from errno.
- Durations span submit to the edge that carried terminal truth,
  via `checked_sub` (never invented, never zero-filled).
- Cross-order completion: whichever of return/callback arrives
  second joins the retained fact and emits once. First terminal
  wins on conflict (counted ambiguous). Gaps complete an id
  immediately (retained truth, else `Unknown`); an
  `IdentityAmbiguous` gap before emission emits `Unknown` and
  counts ambiguous, invalidating even retained truth. `finish`
  drains deterministically by id.
- Submit-first delivery is an adapter prerequisite: edges
  arriving before their submit are counted orphans, never
  joined retroactively.
- Late terminals are compared against tombstoned truth
  (repeat → duplicate, contradiction → ambiguous,
  after-`Unknown` → suppressed duplicate); a Queued return
  after synchronous completion is ambiguous. A late
  identity-ambiguity gap flags the tombstone (counted
  ambiguous, queryable via `is_invalidated`) without
  retracting the emitted record.
- Every edge is classified: counted diagnostics
  (admitted/emitted/orphan/duplicate/ambiguous/admission_failed/
  unfinished), explicitly retained pending state (first terminal
  callback, first Queued return), or explicitly uncounted
  routine progress; tombstones are FIFO-bounded by capacity,
  and eviction re-admits explicitly rather than merging
  silently.
- Payload-v1 (`schemas/kcrypto-lifecycle-v1.schema.json`,
  `schema = kryprobe.kcrypto.lifecycle/v1`) is a standalone
  report-JSON contract for one record; the report validator
  (`validate_lifecycle_v1`) enforces keys, shapes, the version
  const, and terminal/status/duration consistency. Findings
  are input-free by construction: `BadShape` carries key +
  expected shape, `UnknownKey` names the key only, and
  `UnknownVersion` carries nothing — rejected values (which
  could be key material or buffer contents) never enter
  diagnostics; unknown versions fail closed. The duration
  pattern enforces the exact u64 range, matching the validator.
  Schema bytes freeze only after review (no compiled-in pin
  yet).
- Payload-v1 is NOT carried in the v0 event envelope: event-v0
  has no `backend_payload` property and sets
  `additionalProperties: false`, so v0 cannot carry it without
  a versioned envelope change. Envelope carriage is deferred to
  a future envelope ADR; frozen v0 bytes are untouched.

## Consequences

- No BPF/kernel access in core: all ids are opaque; errno values
  are exact native integers, never canonicalized.
- Consumers (T06+) receive at-most-once records per admission
  with explicit `Unknown` where truth is absent, plus
  diagnostic counters. At-most-once does NOT span
  tombstone-eviction plus same-id re-admission: a late edge
  from an evicted lifetime can join the new one. Cross-lifetime
  safety requires lifetime-unique ids (T08 prerequisite), not a
  reducer fix — bounded memory cannot distinguish a replayed
  old edge from a fresh one after eviction. A consumer that
  observes an invalidation via `is_invalidated()` must preserve
  it downstream: eviction discards the flag and T08 ids do not
  recover it.
- Policy gates on lifecycle payloads (T11) can require
  validator-clean as a precondition.

## Enforcement

- `crates/kryprobe-core/tests/kcrypto_lifecycle.rs`: ordering
  oracle, capacity, stats, gap/finish, invalidation (live +
  late), cross-order, conflict and tombstone diagnostics
  (incl. order-independent Unresolved), counter balance,
  Submit-first orphan, tombstone-bound, Q04/Q05/Q08/Q09
  vectors (35 tests).
- `validate::lifecycle_v1` unit vectors: happy shapes plus
  absent/overflow/malformed/version/combination/errno/
  unknown-key/redaction/presence-complete/float-status/
  u64-boundary/newline cases (17 tests).
- `docs/versioning.md` records the new marker; unknown versions
  cannot validate clean.
