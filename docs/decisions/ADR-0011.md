# ADR-0011: fence proof scope — x86-64 TSO + zombie argument (amends ADR-0010)

## Status

Accepted (M1 Task 02, 2026-10-03). Supplements ADR-0010: the close
sequence (detach-first + `CLOSED` + polls + grace/rescan) is
unchanged; only the soundness argument is scoped. ADR-0010 is not
edited in place. One code tightening rides along (deadline honored
on the receipt path — see enforcement).

## Context

External review (codex gpt-6.1-sol max, A3 follow-up N1, triaged
TRUE POSITIVE) found ADR-0010's "airtight (no residual)" claim
overbroad in three places:

1. "Each writer's decrement follows its last write in program
   order — so the terminal reads observe frozen maps" assumes
   program order implies cross-CPU visibility order. That holds
   on x86-64 (TSO: observing the decrement's effect implies all
   program-earlier stores from that CPU are visible) but is
   unproven for plain (non-atomic) BPF stores on weakly-ordered
   architectures. The product scope is Linux x86-64 only
   (README, `docs/lane-environment.md`), so the proof is
   repairable by scoping — but as written it claimed too much.
2. "No new BPF invocation can start past detach" ignores
   trampoline retirement (deferred RCU work on 6.12): a CPU that
   entered the trampoline before the detach lands on it CAN run
   the program after the detach syscall returns. The statement
   needs the zombie argument (below), not silent deletion.
3. The receipt path issued `Quiescent` without checking the
   5 s deadline, contradicting the "timeout never yields
   `Quiescent`" contract (a drain landing in (5 s, 5 s + 5 ms]
   got a receipt).

## Decision

The fence soundness argument is the following scoped proof. It
replaces ADR-0010's "Why this is airtight" section; the mechanism
and sequence are unchanged.

Scope: Linux x86-64, TSO memory model. On any other architecture
the proof does not hold as written (a port needs release/acquire
semantics the current plain-store BPF side cannot express) —
aarch64 is explicitly unproven, not silently covered.

Soundness carrier: `CLOSED` + self-refusal + polls + grace.
Detach-first is the LIVENESS bound (stops new arrivals so the
polls terminate fast under load), not a soundness input. Every
case below holds whether or not detach stopped the invocation:

- Any invocation whose increment executes AFTER `CLOSED` lands
  reads closed and refuses WITHOUT touching data (admit gate
  top-of-path in every hook, verified at all 9 wrappers). This
  covers zombie invocations from deferred trampoline
  retirement: whenever they execute, they self-refuse. Trampoline
  retirement TIMING is therefore irrelevant to soundness.
- Any invocation whose increment executed BEFORE `CLOSED`
  landed is admitted and WILL decrement exactly once (single
  wrapper epilogue; inner early-returns return into the
  wrapper — no admit-without-release path exists, and a leak
  would in any case stick the lane nonzero → `Pending`, loud).
- The polls spin until every lane reads zero; the grace (5 ms,
  >1000x store-visibility latency) converts
  executed-but-invisible increments into visible ones; the
  rescan confirms. An admitted writer stalled mid-program (IRQ/
  SMI preemption) shows its increment at the rescan → polling
  continues. An increment executed between the first read and
  the rescan, or after the rescan, is post-`CLOSED` →
  self-refuses (dataless) by the first case.
- The second all-zero read therefore implies every admitted
  decrement is visible; on x86-64 TSO each writer's data stores
  (program-earlier than its decrement) are visible too. The
  terminal reads observe frozen maps.

Deadline semantics: the 5 s bound caps the WAIT (liveness), and
the receipt path now honors it — a drain observed at/past the
deadline is `Pending` even when double-drained (a 5 s drain
means a sick machine; normal drains are milliseconds). Timeout
never yields `Quiescent`, on the boundary included.

## Consequences

- The hammer test gains a ready barrier (overlap proven, not
  probabilistic) and a terminal read BEFORE stop/join (stability
  immediately after receipt, not just after join) — see
  `finish_session_quiescent_under_hammer_freezes_terminal`.
- The old-order negative control is re-run against the
  strengthened test (documented outcome in the freeze record).
- Any future non-x86-64 port MUST re-prove this ADR (fence
  protocol change, not a docs edit).
