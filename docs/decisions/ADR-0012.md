# ADR-0012: M1 shared userland contract corrections (Stage 2A)

## Status

Accepted (M1 Stage 2A, 2026-10-09). Single-writer: the Stage 2A owner
writes this contract; Stage 2B/2C/2D and Stage 1 consume it. Changes
after dispatch require a new ADR plus coordinator routing — never an
independent invention in each branch. This ADR amends the *userland*
half of ADR-0008 §§(g)–(i) without touching its frozen bytes: v1 schema
bytes, event-v0, lifecycle, and the `KCTX`/fence ABI are unchanged.

## Context

Independent review (gap review G03/G05/G07 plus a read-only Codex audit
of the same base) confirmed the Task01 userland contract cannot carry
M1: every container-only identity keyed as `unresolved` and promoted to
`Unique`; no `SnapshotResponse`/metadata DTOs; the wrong-kernel test
compared no kernels; v1 validation accepted non-hex sessions and never
inspected context members; and the v1 report cannot support replay
(hash-only operation identity, no ledger operands, optional lifetime).
Stage 2B/2C/2D need one frozen, reviewed contract — not three guesses.

## Decision

### (a) Structured identity keys (G03.1/G03.2, D02, D11)

`WorkloadIdentity` keeps its associations, but identity is now a list of
structured [`IdentityKey`](../../crates/kryprobe-core/src/workload/identity.rs)
values — `Container{runtime,id,lifetime}`, `Pod{cluster,uid}`,
`Node{node}`, `AncestorContainer{...}` — compared field-wise. There is
no delimiter-joined string key: `cluster="a:b"/uid="c"` and
`cluster="a"/uid="b:c"` are distinct by construction.

- Container identity is runtime instance + FULL id + lifetime, each
  splitting. A `None`/empty lifetime is explicitly unobserved, never a
  wildcard; a restart under a new lifetime never inherits counts.
- Pod identity is cluster + UID; name/namespace stay display-only.
- The pod key uses the pod's own cluster; when the top-level cluster is
  also present it must agree (`check_consistency`, else refusal).
- `qualify_join` yields `Unique` only for exactly one distinct key,
  `Ambiguous` (sorted structured keys) on collision, `Unresolved` when
  candidates exist but none resolves, and `None` when empty. Unresolved
  candidates never promote; callers keep them in captured-context rows.
- `ContainerRef`/`PodRef` are exported for typed helper construction.

### (b) Evidence vocabulary and verified local binding (G03.4, D07–D09)

Method vocabulary is frozen to six exact strings; relationships are the
typed spec §3.3 enum (`hook_context`, `submitter`,
`completion_context`, `workload_origin`, `consumer`).

- `Verified` requires `hook_context`, a well-ordered validity interval,
  and one kernel-corroborated (method, source) pair:
  (`captured_cgroup`, `KernelCapture`) or (`cgroup_inode_bind`,
  `HostProc`). The latter is the Stage 2B resolver's verified local
  binding (unprivileged tree walk matching a captured cgroup id to a
  live cgroupfs inode). Hook context never verifies origin/submitter/
  completion/consumer claims in M1; `Asserted`/`Stale`/`Ambiguous`
  likewise require `hook_context`, while `Unresolved`/`Unsupported`
  accept any relationship.
- Every supplied validity interval must be ordered, whatever the
  status. Validity is a `ValidityInterval{start_ns,end_ns,clock}` with
  `clock = monotonic_boot` — the `start_ns` domain, never wall clock —
  interpreted within the enclosing snapshot's exact-matched
  kernel/boot scope.
- Metadata/adapter methods cap at `Asserted` whatever source they
  claim; files assert, they never verify.
- All diagnostics are static strings: no supplied method, id, or path
  bytes ever appear in an error.

### (c) Snapshot DTOs, codec, and pure resolution (G03.3, D01, D04)

Typed `MetadataSnapshot`/`MetadataEntry`/`BindingProvenance`,
`SnapshotRequest`/`SnapshotKey`, and the new `SnapshotResponse` with
`ResolvedAssociation`, `SnapshotKeyError`, `ResponseStatus`,
`ChunkInfo`, and exact `SnapshotCounters`, plus the `WorkloadObservation`
enrichment row. Wire field names are frozen by
`schemas/workload-snapshot-v1.schema.json` and
`schemas/workload-metadata-v1.schema.json` (pinned digests in code) and
by serialization-shape tests.

- Codec discipline: byte limits apply to raw bytes BEFORE
  allocation/parsing; count limits apply AFTER parsing
  (`decode_request`/`decode_response`/`decode_metadata`, each with a
  nesting guard on metadata JSON).
- `resolve(request, snapshot)` is pure (captured keys + snapshot, no
  I/O) and the replay entry point: exact kernel/boot scope match per
  key (mismatch → `KernelMismatch`, unknown snapshot kernel →
  `UnknownKernel`); exact cgroup match (none → `Unresolved`, several →
  `Ambiguous`); validity/snapshot-window overlap else `Stale`; the pure
  path asserts at most, never verifies. Responses bind to their
  request (`bind_response_to_request`: session equality, keys drawn
  from and — single-chunk — covering the request exactly once).
- Tail truncation to the 64 KiB budget converts dropped associations to
  `BudgetExceeded` errors (`Truncated` status); an unwritable key set
  refuses outright so the caller splits it across requests/chunks.

### (d) Limits (old preserved, missing pinned)

Preserved exactly: metadata 1,048,576 B / 1024 entries; string 256 B;
request 4096 B; response 65,536 B / 256 associations; kernel tag 128 B;
session 32 lowercase hex. New Stage 2A pins (not pre-existing
requirements): metadata nesting depth 16; resolver cache 256 entries /
tombstones 256; cache TTL 300 s, negative-cache TTL 5 s, minimum
refresh interval 1 s; helper retries 2 past the initial attempt;
helper request timeout 2 s; v2 report 1,048,576 B / 1024 context rows /
1024 dictionary entries. All limits are boundary-tested, including
fail-closed backwards-clock behavior for deadlines/TTLs.

### (e) workload-report-v2 (G05.3/G05.4, D03, D10, replay)

New default `schemas/workload-report-v2.schema.json`
(`kryprobe.workload-report.v2`, pinned digest) with a strict validator.
Every context row carries lifetime (`start_ns` REQUIRED, `0` =
explicit unreadable) plus full native identity inline (`family`, `op`,
`result`, `context`, `algorithm`, `driver`) or a `native_ref` into a
collision-qualified dictionary (ids unique; refs resolve; `kh` agrees).
The report further carries session/execution-kernel identity, a clocked
interval, the authoritative ledger (`system_total`, `per_context_sum`,
`unknown`, `refused_inserts`, saturation flags, consistency,
`gap_unreconciled`), the selector partition, typed selectors + explicit
capture/report scope and grouping, typed metadata availability, and
four independent coverage values. Validator-enforced conservation:

- `unknown = system_total − per_context_sum` (checked) when quiescent;
  unproven exports `gap_unreconciled` with `unknown = 0`, never an
  exact unknown. Quiescent requires unsaturated operands and
  `refused_inserts ≤ unknown`.
- `per_context_sum = Σ contexts[].calls` (checked) and
  `partition.observed = per_context_sum`; unscoped reports match their
  whole observed population; `report_scope` agrees with the selector
  kind. Closed allowlisted workload/attribution objects (full 64-hex
  container ids); evidence cross-rules reused from (b).

### (f) Legacy v1: tightened validation, frozen bytes (G05.1/G05.2, E01, D13)

The v1 schema file is byte-untouched (digest `6d5cf345969d3ff7`,
pinned). Its validator now enforces every stated requirement —
lowercase-hex sessions, all nested required keys/types/bounds, closed
key sets — and pins/detects schema drift like event-v0. V1's stated
gaps (untyped workload/attribution members, optional lifetime, no
ledger/native identity) stay as documented limitations:
`v1_scope_support` renders a stored partition with four explicit
limitations or refuses scoped re-evaluation. The old-format test now
validates the v0 golden through the real v0 validator (the
writer-output-vs-golden byte check lives in `report_golden.rs`).

### (g) Checked construction and qualified differences (D05, D06, D12)

`ScopePartition`, `UnknownByDifference`, and `ChunkInfo` deserialize
only through their checked constructors (recomputed/verified on
decode). `UnknownByDifference::compute` keeps its signature for the
Stage-1-owned capture caller (unsaturated-operands precondition,
static diagnostics); saturation-qualified callers use
`compute_qualified(consistency, population, system, per_context)`,
which refuses unproven/saturated/contradictory/malformed-population
inputs with typed errors. `ContextQualification.boundary` is an owned
decodable enum (wire-identical `api_return`).

## Considered options (rejected)

- **String keys with escaping:** rejected — escaping rules are a second
  contract to get wrong; structured keys compare correctly by
  construction.
- **Verifying metadata assertions by quorum:** rejected — no quorum of
  assertions corroborates a kernel binding; only capture and the
  inode-bound walk verify.
- **Extending v1 in place:** rejected — ADR-0008 freezes v1; replay
  needs fields v1 cannot carry, so v2 is a new schema.
- **Saturation-tolerant exact unknown:** rejected — a saturated operand
  no longer measures its population; exactness refuses.

## Consequences

- Stage 2B implements the helper IPC/resolver against (b)–(d); Stage 2C
  renders/replays (e) reusing the frozen validators; Stage 2D evaluates
  scopes over (a)/(b)/(e) with the eight frozen fixtures in
  `crates/kryprobe-report/tests/fixtures/workload-v2/`.
- Stage 1 must agree the capture-integrity field mapping (ledger
  operands, saturation flags, `refused_inserts`, fence consistency)
  before integration; the `ctx_unknown_from_totals` caller migrates to
  `compute_qualified` under Stage 1/3 ownership (not edited here).
- Unscoped v1/v2 partitions match their whole observed population by
  convention; pod/runtime selectors and lifecycle relationships refuse
  until M2/M3.

## Enforcement / provenance

- `crates/kryprobe-core/src/workload/**` + `workload_contract`,
  `workload_identity_keys`, `workload_snapshot` tests pin (a)–(d),(g).
- `schemas/workload-{snapshot,metadata}-v1.schema.json`,
  `schemas/workload-report-v2.schema.json` (+ pinned digests) and
  `kryprobe-report/src/validate/workload_{v1,v2}.rs` (+ `workload_v2`
  fixture tests, fixed `workload_dispatch`) pin (e)–(f).
- `cargo xtask check`, `cargo xtask verify generated`, and the targeted
  workload suites stay green; the v1 schema bytes are untouched.

## Amendment (2026-10-10, Round 2: B2 freeze follow-up)

Codex B2 returned FREEZE-BLOCKED on the R1 freeze (`a49ef56`). This
amendment fixes exactly the blocking list, in one commit, with a named
oracle per finding. Nothing above is rewritten: the rules below
supersede the cited R1 behaviors from this date forward.

### (a2) Compatible-association joins (G03.2)

`qualify_join` compares per-candidate key SETS, not the union of keys:
the associations within one candidate are compatible facets of a single
workload, so one candidate never collides with itself however many
facets it carries; only disagreeing candidates yield `Ambiguous` (with
every competing key retained, sorted). Oracle:
`compatible_associations_within_one_candidate_stay_unique`.

### (c2) Capture-interval coverage and staleness (D01)

`SnapshotRequest` gains the additive, wire-optional `capture_interval`
(the counted interval, monotonic ns, omitted when unestablished).
Resolution asserts a binding only when its validity window COVERS the
whole capture interval — overlap alone never asserts, and an absent
capture interval or absent validity window cannot establish coverage.
Explicit `Stale` bindings are honored (never promoted). Uncovered
counts stay unknown, never asserted: `Stale` (identity kept, counted
unresolved) when a validity window exists but does not cover,
`Unresolved` (no identity) when none does. The snapshot window no
longer participates in the applicability check; it remains collector
metadata. Oracles: `covered_capture_asserts`,
`uncovered_capture_with_validity_stays_stale`,
`uncovered_capture_without_validity_stays_unresolved`,
`absent_capture_never_asserts`, `explicit_stale_status_is_honored`.
This supersedes coordinated guess 9 (overlap-based staleness).

### (c3) Kernel-scoped response binding (B2 reply binding)

`bind_response_to_request` requires kernel-scope agreement: every
served association must answer a key inside the response's kernel
scope; only typed kernel refusals (`KernelMismatch`, `UnknownKernel`)
may come from a foreign kernel. `SnapshotResponse::validate` now also
enforces kernel-tag bounds. Oracles:
`bound_response_requires_matching_kernel_scope`,
`foreign_kernel_typed_refusal_still_binds`,
`response_kernel_bounds_are_checked`.

### (c4) Resolution coherence (B2 coherence)

A cgroup-0 key never resolves (the unknown-cgroup population stays
unknown with no identity, whatever the file claims for id 0), and a
single match with no established identity stays `Unresolved` (usable
statuses require an identity, mirroring `WorkloadObservation`).
Counters follow from statuses via the existing recount. Oracles:
`cgroup_zero_with_identity_stays_unknown` (+ the strengthened
`unresolved_cgroup_zero_stays_unknown`),
`identityless_match_stays_unresolved`.

### (c5) Closed IPC decoders (B2 schemas)

Every IPC DTO struct (requests, keys, responses, associations, errors,
counters, chunks, snapshots, entries, provenance, intervals,
identities, evidence, observations, contexts, partitions, differences,
and their wire shapes) carries `deny_unknown_fields`: unknown fields
refuse instead of being discarded, matching the closed schemas.
Oracles: `unknown_request_fields_refuse`,
`unknown_response_fields_refuse`, `unknown_metadata_fields_refuse`.

### (d2) Typed refusal details (D09)

`SnapshotKeyError.detail` is the closed enum `SnapshotKeyDetail`
(`kernel_differs`, `kernel_unknown`, `budget_dropped`,
`unsupported_key`) with static rendering: arbitrary strings never
decode. The snapshot schema pins the same vocabulary. Oracles:
`arbitrary_error_detail_refuses_decode`,
`typed_error_details_round_trip`.

### (e2) Unscoped partitions (G05.3)

The v2 validator enforces the ADR rule the R1 fixture constructor
violated: an unscoped report matches its WHOLE observed population
(`matched` = observed, `nonmatched` = 0, `unknown_match` = 0).
Oracle: `unscoped_split_partition_refuses`. This promotes coordinated
guess 3 from convention to enforced rule.

### (e3) Absent allocation drivers (G05.4)

The v2 `driver` field is optional: allocation captures carry zero
driver bytes, so an absent driver validates as explicitly unavailable
while present-but-empty refuses. Distinct native tuples sharing one
`kh` stay representable — dictionary refs disambiguate by `dict_id`,
and `kh`-only joins must retain ambiguity (Stage 2D). Oracles:
`absent_driver_validates_as_unavailable`, `empty_driver_refuses`,
`distinct_natives_sharing_kh_are_representable`.

### (e4) Report-level combination rules (D02, D03, D10)

- D02: `workload.cluster` must agree with `workload.pod.cluster` when
  both are present, mirroring core `check_consistency`. Oracle:
  `conflicting_workload_cluster_refuses`.
- D03: every digit string must parse as `u64` — including context
  `start_ns`, unreferenced dictionary `kh` values, and selector
  `cgroup_id`. Oracle: `unrepresentable_digit_strings_refuse`.
- D10: `selectors.container` carries runtime + id ONLY (no lifetime),
  matching the closed schema. Oracle:
  `selector_container_lifetime_refuses`.

### (g2) Tagged difference populations (D06)

`CountOperand` tags its own population: `compute_qualified` checks both
tags well-formed and EQUAL (new typed `PopulationMismatch` refusal) —
no silent caller assertion. `QualifiedDifference` deserializes only
through checked construction (recomputed magnitude, validated tag,
`Quiescent` fence only). `UnknownByDifference::compute` keeps its
signature for the Stage-1-owned caller. Oracles:
`population_mismatch_refuses`,
`unproven_qualified_difference_refuses_decode`.

### (h) Fixtures, oracles, and pins

- All eight v2 fixtures now use native context codes (proc = 0,
  kthread = 1; reserved softirq = 2 never appears) with process starts
  at or before the capture end. Oracle:
  `fixtures_use_native_context_codes_and_ordered_starts`.
- `ObservationBoundary` gains its deserialize round-trip oracle from
  an owned buffer (D12):
  `observation_boundary_round_trips_from_owned_buffer`.
- Recomputed pins: snapshot `717b522c7e2d7907`, v2 `92e9d634369c605c`;
  metadata `bf8a6a4cba2b04d4` and v1 `6d5cf345969d3ff7` UNCHANGED
  (v1 bytes byte-identical, 3,578 bytes).

### Round 3 ingress follow-up (2026-10-10)

Codex B3 returned AMENDMENT-BLOCKED on the R2 amendment (`0e9a394`):
the R2 producer rules are sound, but the receiving boundaries still
accepted contradictory attribution, and two frozen fixtures asserted
bindings that expired before their counted interval. This follow-up
closes exactly those ingress gaps, in one commit, with a named oracle
per finding. Nothing above is rewritten: the rules below supersede the
cited R2 behaviors from this date forward.

### (c6) Ingress coherence (B3 coherence escape)

`SnapshotResponse::validate` now enforces the same coherence the
producer guarantees: usable statuses (`Verified`/`Asserted`/`Stale`)
require an established identity — mirroring `WorkloadObservation` —
and cgroup-0 keys carry no identity, whatever a received reply claims.
The B3 escape payload (matching session/kernel/key, Complete single
chunk, exact counters, Asserted `metadata_file` evidence, empty
identity — or a cgroup-zero key with an identity) refuses at decode,
validate, and bind alike, since decode and bind route through
validation. Oracles: `ingress_asserted_without_identity_refuses`,
`ingress_cgroup_zero_with_identity_refuses`.

### (c7) Receiving-boundary temporal validation (B3 capture applicability)

Coverage is checked where the intervals meet, on receipt as well as on
production:

- `bind_response_to_request` refuses an `Asserted`/`Verified`
  association unless its validity window COVERS the request's counted
  capture interval (reusing the D01 coverage predicate). A capture-less
  request or a windowless reply cannot establish coverage, so such
  bindings refuse — mirroring `absent_capture_never_asserts` for
  received replies. Kernel corroboration proves the binding, not its
  applicability to the counted interval, so `Verified` obeys the same
  rule. `Stale` and weaker statuses assert nothing about the counted
  interval and carry no temporal requirement. Oracles:
  `bind_refuses_asserted_when_validity_does_not_cover_capture` (with a
  covering positive control),
  `bind_refuses_verified_when_validity_does_not_cover_capture`,
  `bind_refuses_asserted_without_coverable_window`.
- The v2 validator enforces evidence-vs-capture/report-interval
  agreement inside `validate_attribution_rules`, which now receives the
  parsed report interval: asserted/verified attribution requires a
  validity window covering the whole counted interval. A defective
  interval refuses on its own finding without cascading. Oracle:
  `expired_binding_asserted_refuses` (with covering and stale positive
  controls).

### (c8) Closed method vocabulary at ingress (B3 IPC vocabulary)

`AttributionEvidence::validate` enforces the frozen six-method
vocabulary for EVERY status, matching the snapshot schema: a
schema-invalid method refuses decode even on
stale/unresolved/ambiguous/unsupported associations. The rule is
vocabulary membership, not a new status pairing — an in-vocabulary
method on an unusual status still decodes. Oracle:
`schema_invalid_evidence_method_refuses_decode` (with a positive
control).

### (e5) Asserted fixture windows (B3 canonical fixtures)

`asserted-metadata.json` and `matching-violation.json` now carry
validity `[100,1000]`, covering their capture interval `[100,1000]`
for their Asserted/matched claims (previously `[100,200]`, expired
before the processes started). Oracle:
`asserted_fixture_bindings_cover_capture` plus the v2
`expired_binding_asserted_refuses` refusal oracle.

### (h2) Round-3 pins

No schema bytes changed, so no pin moves: snapshot `717b522c7e2d7907`,
v2 `92e9d634369c605c`, metadata `bf8a6a4cba2b04d4`, v1
`6d5cf345969d3ff7` — all unchanged (v1 bytes byte-identical).
