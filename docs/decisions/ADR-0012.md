# ADR-0012: M1 shared userland contract corrections (Stage 2A)

## Status

Accepted (M1 Stage 2A, 2026-10-09). Single-writer: the Stage 2A owner
writes this contract; Stage 2B/2C/2D and Stage 1 consume it. Changes
after dispatch require a new ADR plus coordinator routing — never an
independent invention in each branch. This ADR amends the *userland*
half of ADR-0008 §§(g)–(i) without touching its frozen bytes: v1 schema
bytes, event-v0, lifecycle, and the `KCTX`/fence ABI are unchanged.

## Context

Independent review (gap review G03/G05/G07 plus a read-only Codex audit
of the same base) confirmed the Task01 userland contract cannot carry
M1: every container-only identity keyed as `unresolved` and promoted to
`Unique`; no `SnapshotResponse`/metadata DTOs; the wrong-kernel test
compared no kernels; v1 validation accepted non-hex sessions and never
inspected context members; and the v1 report cannot support replay
(hash-only operation identity, no ledger operands, optional lifetime).
Stage 2B/2C/2D need one frozen, reviewed contract — not three guesses.

## Decision

### (a) Structured identity keys (G03.1/G03.2, D02, D11)

`WorkloadIdentity` keeps its associations, but identity is now a list of
structured [`IdentityKey`](../../crates/kryprobe-core/src/workload/identity.rs)
values — `Container{runtime,id,lifetime}`, `Pod{cluster,uid}`,
`Node{node}`, `AncestorContainer{...}` — compared field-wise. There is
no delimiter-joined string key: `cluster="a:b"/uid="c"` and
`cluster="a"/uid="b:c"` are distinct by construction.

- Container identity is runtime instance + FULL id + lifetime, each
  splitting. A `None`/empty lifetime is explicitly unobserved, never a
  wildcard; a restart under a new lifetime never inherits counts.
- Pod identity is cluster + UID; name/namespace stay display-only.
- The pod key uses the pod's own cluster; when the top-level cluster is
  also present it must agree (`check_consistency`, else refusal).
- `qualify_join` yields `Unique` only for exactly one distinct key,
  `Ambiguous` (sorted structured keys) on collision, `Unresolved` when
  candidates exist but none resolves, and `None` when empty. Unresolved
  candidates never promote; callers keep them in captured-context rows.
- `ContainerRef`/`PodRef` are exported for typed helper construction.

### (b) Evidence vocabulary and verified local binding (G03.4, D07–D09)

Method vocabulary is frozen to six exact strings; relationships are the
typed spec §3.3 enum (`hook_context`, `submitter`,
`completion_context`, `workload_origin`, `consumer`).

- `Verified` requires `hook_context`, a well-ordered validity interval,
  and one kernel-corroborated (method, source) pair:
  (`captured_cgroup`, `KernelCapture`) or (`cgroup_inode_bind`,
  `HostProc`). The latter is the Stage 2B resolver's verified local
  binding (unprivileged tree walk matching a captured cgroup id to a
  live cgroupfs inode). Hook context never verifies origin/submitter/
  completion/consumer claims in M1; `Asserted`/`Stale`/`Ambiguous`
  likewise require `hook_context`, while `Unresolved`/`Unsupported`
  accept any relationship.
- Every supplied validity interval must be ordered, whatever the
  status. Validity is a `ValidityInterval{start_ns,end_ns,clock}` with
  `clock = monotonic_boot` — the `start_ns` domain, never wall clock —
  interpreted within the enclosing snapshot's exact-matched
  kernel/boot scope.
- Metadata/adapter methods cap at `Asserted` whatever source they
  claim; files assert, they never verify.
- All diagnostics are static strings: no supplied method, id, or path
  bytes ever appear in an error.

### (c) Snapshot DTOs, codec, and pure resolution (G03.3, D01, D04)

Typed `MetadataSnapshot`/`MetadataEntry`/`BindingProvenance`,
`SnapshotRequest`/`SnapshotKey`, and the new `SnapshotResponse` with
`ResolvedAssociation`, `SnapshotKeyError`, `ResponseStatus`,
`ChunkInfo`, and exact `SnapshotCounters`, plus the `WorkloadObservation`
enrichment row. Wire field names are frozen by
`schemas/workload-snapshot-v1.schema.json` and
`schemas/workload-metadata-v1.schema.json` (pinned digests in code) and
by serialization-shape tests.

- Codec discipline: byte limits apply to raw bytes BEFORE
  allocation/parsing; count limits apply AFTER parsing
  (`decode_request`/`decode_response`/`decode_metadata`, each with a
  nesting guard on metadata JSON).
- `resolve(request, snapshot)` is pure (captured keys + snapshot, no
  I/O) and the replay entry point: exact kernel/boot scope match per
  key (mismatch → `KernelMismatch`, unknown snapshot kernel →
  `UnknownKernel`); exact cgroup match (none → `Unresolved`, several →
  `Ambiguous`); validity/snapshot-window overlap else `Stale`; the pure
  path asserts at most, never verifies. Responses bind to their
  request (`bind_response_to_request`: session equality, keys drawn
  from and — single-chunk — covering the request exactly once).
- Tail truncation to the 64 KiB budget converts dropped associations to
  `BudgetExceeded` errors (`Truncated` status); an unwritable key set
  refuses outright so the caller splits it across requests/chunks.

### (d) Limits (old preserved, missing pinned)

Preserved exactly: metadata 1,048,576 B / 1024 entries; string 256 B;
request 4096 B; response 65,536 B / 256 associations; kernel tag 128 B;
session 32 lowercase hex. New Stage 2A pins (not pre-existing
requirements): metadata nesting depth 16; resolver cache 256 entries /
tombstones 256; cache TTL 300 s, negative-cache TTL 5 s, minimum
refresh interval 1 s; helper retries 2 past the initial attempt;
helper request timeout 2 s; v2 report 1,048,576 B / 1024 context rows /
1024 dictionary entries. All limits are boundary-tested, including
fail-closed backwards-clock behavior for deadlines/TTLs.

### (e) workload-report-v2 (G05.3/G05.4, D03, D10, replay)

New default `schemas/workload-report-v2.schema.json`
(`kryprobe.workload-report.v2`, pinned digest) with a strict validator.
Every context row carries lifetime (`start_ns` REQUIRED, `0` =
explicit unreadable) plus full native identity inline (`family`, `op`,
`result`, `context`, `algorithm`, `driver`) or a `native_ref` into a
collision-qualified dictionary (ids unique; refs resolve; `kh` agrees).
The report further carries session/execution-kernel identity, a clocked
interval, the authoritative ledger (`system_total`, `per_context_sum`,
`unknown`, `refused_inserts`, saturation flags, consistency,
`gap_unreconciled`), the selector partition, typed selectors + explicit
capture/report scope and grouping, typed metadata availability, and
four independent coverage values. Validator-enforced conservation:

- `unknown = system_total − per_context_sum` (checked) when quiescent;
  unproven exports `gap_unreconciled` with `unknown = 0`, never an
  exact unknown. Quiescent requires unsaturated operands and
  `refused_inserts ≤ unknown`.
- `per_context_sum = Σ contexts[].calls` (checked) and
  `partition.observed = per_context_sum`; unscoped reports match their
  whole observed population; `report_scope` agrees with the selector
  kind. Closed allowlisted workload/attribution objects (full 64-hex
  container ids); evidence cross-rules reused from (b).

### (f) Legacy v1: tightened validation, frozen bytes (G05.1/G05.2, E01, D13)

The v1 schema file is byte-untouched (digest `6d5cf345969d3ff7`,
pinned). Its validator now enforces every stated requirement —
lowercase-hex sessions, all nested required keys/types/bounds, closed
key sets — and pins/detects schema drift like event-v0. V1's stated
gaps (untyped workload/attribution members, optional lifetime, no
ledger/native identity) stay as documented limitations:
`v1_scope_support` renders a stored partition with four explicit
limitations or refuses scoped re-evaluation. The old-format test now
validates the v0 golden through the real v0 validator (the
writer-output-vs-golden byte check lives in `report_golden.rs`).

### (g) Checked construction and qualified differences (D05, D06, D12)

`ScopePartition`, `UnknownByDifference`, and `ChunkInfo` deserialize
only through their checked constructors (recomputed/verified on
decode). `UnknownByDifference::compute` keeps its signature for the
Stage-1-owned capture caller (unsaturated-operands precondition,
static diagnostics); saturation-qualified callers use
`compute_qualified(consistency, population, system, per_context)`,
which refuses unproven/saturated/contradictory/malformed-population
inputs with typed errors. `ContextQualification.boundary` is an owned
decodable enum (wire-identical `api_return`).

## Considered options (rejected)

- **String keys with escaping:** rejected — escaping rules are a second
  contract to get wrong; structured keys compare correctly by
  construction.
- **Verifying metadata assertions by quorum:** rejected — no quorum of
  assertions corroborates a kernel binding; only capture and the
  inode-bound walk verify.
- **Extending v1 in place:** rejected — ADR-0008 freezes v1; replay
  needs fields v1 cannot carry, so v2 is a new schema.
- **Saturation-tolerant exact unknown:** rejected — a saturated operand
  no longer measures its population; exactness refuses.

## Consequences

- Stage 2B implements the helper IPC/resolver against (b)–(d); Stage 2C
  renders/replays (e) reusing the frozen validators; Stage 2D evaluates
  scopes over (a)/(b)/(e) with the eight frozen fixtures in
  `crates/kryprobe-report/tests/fixtures/workload-v2/`.
- Stage 1 must agree the capture-integrity field mapping (ledger
  operands, saturation flags, `refused_inserts`, fence consistency)
  before integration; the `ctx_unknown_from_totals` caller migrates to
  `compute_qualified` under Stage 1/3 ownership (not edited here).
- Unscoped v1/v2 partitions match their whole observed population by
  convention; pod/runtime selectors and lifecycle relationships refuse
  until M2/M3.
