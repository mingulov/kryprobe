# ADR-0003: Process identity is (pid, start-time), never numeric pid alone

## Status

Accepted (reconstructed from the tree — see Provenance).

## Context

Linux pids recycle. Any scope that admits "pid N" and observes it
later risks observing a different process after N exits and the
kernel reissues N — a silent target-confusion hole in an observer
whose whole product is attribution.

## Decision

Identity is the (pid, start-time) pair: the pid plus field 22 of
`/proc/<pid>/stat` read at admit time (`FanoutMember` in
`crates/kryprobe-privilege/src/fanout.rs`).

Generation semantics (fork/exec/reuse):

- Fork creates a new process lifetime: a child is never the same
  member as its parent, even before it execs.
- Exec keeps the member (same lifetime, new image).
- Pid reuse never resurrects a member: a (pid, start-time) pair
  that stops matching is gone, and re-admission is a new member.
- The drain-side join keys on the same pair, so attribution cannot
  slide across a reuse window.

Admission policy built on this identity lives in
`docs/attach-policy.md` (observability is exactly inspectability);
the mechanism is entered only through
`LocalPrivilegedAuthority::resolve_scope` / `refresh_fanout`.

## Consequences

Positive:

- Target confusion across pid reuse is structurally impossible —
  there is no code path that observes "pid N" without its start-time.
- Fork/exec/reuse have one documented semantic shared by admission
  and attribution.

Negative:

- Every member carries 8 extra bytes and every admit path reads
  `/proc/<pid>/stat` — negligible, but load-bearing reads that must
  stay bounded (they are: the inspection facet caps `/proc` reads).

## Provenance

No ADR file shipped with the tree; this record reconstructs the
decision from its mechanism (`fanout.rs`, `attach-policy.md`).
The semantics above are the code's behavior — if the code and this
file ever disagree, the code wins and this file must be amended.
