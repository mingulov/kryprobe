# ADR-0008: M1 workload-context accounting contract (ctx-v1)

## Status

Accepted (M1 Task 01, 2026-10-02). Single-writer: Task 01 owns this
contract; Task 02 consumes it, changes require a new ADR. This ADR
freezes the versioned `ctx-v1` accounting contract alongside the
frozen event-v0/agglayouts — it never rewrites them in place.

## Context

The K5 `KWHO` table attaches one first-seen cgroup/uid to a whole
`(kh, tgid)` row: a process that migrates cgroup A→B (or drops root)
keeps counting into the stale row (spec F01, acceptance A01/A02).
Task 00b measured that container-originated dm-crypt crypto executes
in kcryptd kworkers (0/175,350 recorded calls in the container's
cgroup), so the contract must record *observed execution context*
and never infer an originator. The v020-aggregate-stop design
(`DESIGN.md` Option B) left the exact stop fence to a versioned BPF
writer protocol sequenced with M1 Task 01/02.

## Decision

### (a) Context key layout (`KCtxKey` v1, 32 bytes)

`repr(C)`, alignment 8, zero padding. Field order is the wire order:

| Offset | Size | Field | Meaning |
|--------|------|-------|---------|
| 0 | u64 | `kh` | `kh_of` row hash over the full `KAgg` row (fam/op/res/ctx + names), same bytes as K5 |
| 8 | u64 | `cgroup` | `bpf_get_current_cgroup_id` at event time; 0 = unreadable (own bucket, never merged) |
| 16 | u32 | `tgid` | thread-group id at event time |
| 20 | u32 | `uid` | low 32 of uid/gid at event time |
| 24 | u64 | `start_ns` | task start time (boot-time ns) via a BTF-resolved offset; 0 = unreadable (own bucket, never merged) |

Size is 32, alignment 8. Migration (cgroup change), uid change, and
TGID reuse across lifetimes each split rows by construction (A01/A02).
Threads sharing a TGID share a row unless their event-time cgroups
differ (no forced thread-level accounting). `cgroup == 0` and
`start_ns == 0` rows are explicit unknown populations, not wildcards.

Context value (`VCtx`, 56 bytes): `calls, bytes, ok, errors, queued,
first_ns, last_ns` (all u64, same fold semantics as `VAgg` minus the
always-zero `lat` histogram — C4 admits no durations from a single
edge, so `ctx-v1` does not ship 64 dead bytes per lane).

### (b) Per-CPU memory arithmetic

New map `KCTX: PerCpuHashMap<KCtxKey, VCtx>`, `max_entries = 1024`
(see (c)). Per-entry bytes at N possible CPUs:

```text
entry(N) = 32 + 56 * N        (key shared, value per lane)
```

Lower bound: kernel htab bucket/slab overhead is additional and is
measured, not modeled, in Task 05. Endpoints at the loader's existing
topology bounds (`possible_cpus`, 1..=65,536):

| N (possible CPUs) | Per entry | Full 1024-entry map |
|---|---|---|
| 1 (min) | 88 B | 90,112 B (88.0 KiB) |
| 12 (reference host) | 704 B | 720,896 B (704 KiB) |
| 1024 (realistic ceiling) | 57,376 B | 58,753,024 B (56.03 MiB) |
| 65,536 (loader max) | 3,670,048 B | 3,758,129,152 B (~3.5 GiB; kernel ENOMEM is the backstop) |

No new userspace CPU-count refusal: consistent with the KWHO
precedent (2048 × (16 + 80N)); absurd topologies already refuse in
`possible_cpus`, and map-creation ENOMEM surfaces as a typed loader
error. Task 02/05 measure the capture-only increment on 4K + N-cgroup
+ churn legs before enrichment exists.

### (c) Capacity

`KCTX max_entries = 1024` context rows. Cardinality class matches the
observed workload: identities × cgroups × lifetimes. At 1024 rows the
map holds, e.g., 64 crypto identities × 16 contexts. Exhaustion
behavior is (d), never silent merge.

### (d) Full-map policy: refuse-new with visible loss

On a full `KCTX`, insert refuses; the observation still increments
`KTOT` (the system ledger never loses a counted call, F01.6) and:

1. increments the exact per-CPU counter `KCTX_DROPS`
   (`PerCpuArray<u64>`, 1 slot — a real count, not a saturating flag);
2. emits one `KCTL_CTX_OVERFLOW` ring event per `(kh)` (new `KCtl.kind`
   value 6; the 48-byte ring layout is unchanged).

Refused calls therefore land in the unknown population of (e)
automatically (present in `KTOT`, absent from `KCTX`). LRU eviction
was considered and rejected: evicting attributed history rewrites the
past and can reattribute churn to the wrong survivor. Refused counts
stay visible as `KCTX_DROPS` plus the unknown-by-difference row;
`who_drops_inc` (saturating u8) remains a dropped-something flag and
is never an operand of (e).

### (e) Unknown as system-total-minus-per-context

From a *consistent stop snapshot* (all reads after fence completion,
see below), per `(kh)` group and globally:

```text
unknown_calls = KTOT.calls − Σ KCTX[*].calls
```

Rules: the same counted population (same fence bound, same `kh`
coverage) on both sides; the subtraction is checked — a negative
difference (`ΣKCTX > KTOT`) surfaces typed
(`ContradictorySnapshot`), never saturates to zero; saturation of any
input counter likewise refuses the receipt. Unknown-by-difference is
the *only* unknown magnitude; the 255-cap counters never feed it.
Without a `Quiescent` receipt the snapshot is `Unproven` and exports
`snapshot_gap_unreconciled` (Option A naming), not an exact unknown.

### (f) Proved writer admission/close fence (M1 control ABI v1)

One new mmap-capable array map `KCTLFENCE` (1 × u64): bit 63 =
`CLOSED`, bits 0..62 = active-writer count. Userspace and BPF perform
compatible atomics on the same word; plain `BPF_MAP_UPDATE_ELEM`
overwrite of the live word is forbidden.

1. Initialize `CLOSED=0, count=0` before attach; after all points are
   ready, record the start lower bound and open admission once.
2. At the very beginning of **every** aggregate hook, atomically
   increment and inspect the returned prior `CLOSED` bit. A closed
   entrant immediately decrements and touches no data map/ring.
3. An admitted hook does all work (every `KDROPS` early-return path,
   `KTOT`/`KCTX`, `KIDN`/`KRING`, who/joins); a single wrapper
   epilogue decrements exactly once after its last write. No unbounded
   BPF loop or target-controlled allocation.
4. Stop atomically sets `CLOSED` (`fetch_or`, `SeqCst`); every accepted
   increment is ordered before it; later entrants refuse without data
   writes. Wait for count == 0 with a fixed deadline/poll bound.
5. At zero, record the fence-completion upper bound, close all owned
   links, join/drain, then read every final map/counter. Sequential
   multi-key walks are coherent: no admitted data can appear after
   the bound. Late closed entrants touch only the control word.
6. On timeout/control failure: still close links and clean up, but
   produce no `Quiescent` receipt and no exact difference. Counter
   overflow (63 bits: unreachable — 2^63 concurrent hooks),
   unsupported atomics/mapping, or a missed epilogue is refusal,
   never wrap.

BPF-side ordering (acquire increment / release decrement codegen) and
supported-architecture behavior require source/verifier review in
Task 02 before acceptance; this ADR specifies the protocol, Task 02
proves the codegen. Required interleaving tests (Task 02): writer
paused before the admission RMW, after admission but before `KTOT`,
between `KTOT`/`KCTX`, and before release; close refuses later
entrants and waits for every earlier admitted writer; timeout cannot
yield `Quiescent`; multiple CPUs/keys; counter-saturation bounds; the
true-map-full control. Two stable map reads are never the receipt.

### (g) Pure model: identities, evidence, scope

New crate-surface types in `kryprobe-core::workload` (pure: no OS
reads, no I/O; `std` + `serde` allowed). Names follow spec §5.4:

- `ContextIdentity`: captured `kh`, `cgroup` (0 = unreadable),
  `tgid`, `uid`, `start_ns` (0 = unreadable), `execution_kind`
  (`proc`/`kthread`/`softirq-reserved`/`unknown`). `softirq` mirrors
  `KCTX_SOFTIRQ`: reserved, never written by BPF (no stable in-BPF
  detector); softirq executions misattribute to proc/kthread (known
  limitation, carried from K5).
- `ContextQualification`: which boundary properties were established
  (`hook_context`, `api_return` boundary, lifetime observed/inferred-
  absent, cgroup observed/unreadable).
- `WorkloadIdentity`: optional container/pod/cluster/node/ancestor
  associations. Pod identity is the UID; name+namespace are
  display/selection metadata only — deleting and recreating a pod
  under the same name yields a new identity (tested).
- `AttributionEvidence`: relationship, method, source, `status ∈
  {verified, asserted, unresolved, ambiguous, stale, unsupported}`,
  validity interval. No confidence percentages. Metadata-file content
  is `asserted` unless corroborated; container-ID-looking cgroup
  names are candidates until checked.
- `WorkloadObservation`: an existing observation reference plus
  context and enrichment.
- `ScopeDecision`: `Match` / `NonMatch` / `Unknown`, with the
  partition invariant `observed = matched + nonmatched +
  unknown_match` (checked u64 arithmetic) per fixed population and
  selector. Hook context, workload origin, unknown context, and
  unknown selector match are four distinct concepts with distinct
  types — an unknown context is never a host workload, and an
  unknown match never counts as a confirmed match.

Collision handling: hashes (`kh`, identity hashes) are indexes, not
proof. An ambiguous join yields `ambiguous` status; qualified counts
stay in their rows and are never merged across ambiguous identities.
A synthetic collision test is required (Task 01 unit on the pure
qualifier; Task 02 fixture on the reader).

### (h) Helper snapshot DTOs and typed unavailability

Task 01 defines the bounded snapshot IPC the Task 03 helper
implements; Task 04 integrates the launcher. Budgets (hard caps,
refusal beyond):

| Item | Bound |
|---|---|
| Metadata file bytes | ≤ 1,048,576 |
| Metadata entries | ≤ 1024 |
| String field (id/name/label) | ≤ 256 B |
| Snapshot request | ≤ 4,096 B |
| Snapshot response | ≤ 65,536 B, ≤ 256 associations |
| Cgroup path fields | REFUSED in v1 (no allowlist ADR yet; §9.3) |
| Session id | 128-bit random, hex 32 chars |
| Kernel identity string | ≤ 128 B |

`MetadataUnavailable` is typed: `NoPrincipal` (root invocation with
no trustworthy non-root user), `HelperRefused`, `BudgetExceeded`,
`UnsupportedEnvironment`, `ParseFailed`. The resolver never guesses
from environment variables and never parses metadata as root.

### (i) Schemas and dispatch

New `schemas/workload-report-v1.schema.json` with validator
`kryprobe-report::validate::workload_v1`, freeze pin (FNV over
compiled-in bytes) and drift detection mirroring event-v0.
`schema = "kryprobe.workload-report.v1"` dispatches; unknown schema
values refuse typed. `report FILE` validates and renders the new
format. Existing `json`/`jsonl`/event-v0/lifecycle bytes are
unchanged (golden-pinned). Cgroup IDs render as decimal strings
(no JSON precision loss); paths are absent until the allowlist ADR.

## Considered options (rejected)

- **Context in the `KAgg` key (wider KAGG):** rejected — rewrites the
  frozen aggregate rows and multiplies the 260-byte key by context
  cardinality; the sidecar `KCTX` keeps system counts byte-stable.
- **Bounded context-ID table + full-identity compare:** viable
  fallback if `KCTX` memory proves excessive on the Task 02 gate; not
  the reference (extra indirection, same fence needs).
- **LRU eviction:** rejected — rewrites attributed history (see (d)).
- **Unknown from `who_drops_inc`:** rejected — saturating u8 flag,
  not a count (see (e)).
- **Inferring workload origin for kthread crypto:** rejected — Task
  00b proves the originator is unrecoverable at this layer; per-cgroup
  views are meaningful for process-context crypto only.

## Consequences

- Task 02 implements exactly this layout/fence; any deviation needs a
  new ADR. Task 03 implements the helper against (h); Task 04 renders
  `workload-json` and enforces the partition invariant in views.
- dm-crypt/XFRM-receive crypto reports kthread/root context with an
  explicit documented limitation; M1 stays a correctness fix, and
  per-consumer value shifts toward M3 classification (00b scope note).
- Hot-path cost grows (wider key, admission RMWs); the Task 02
  capture-only gate bounds it before enrichment exists.
